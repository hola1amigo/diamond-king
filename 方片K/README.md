# 方片 K 五人网络版

在本目录运行 `npm start`（或 `node server.js`），默认端口 3000，可用环境变量 PORT 修改。

## 开局

1. 所有玩家打开同一个首页网址，输入昵称并点击“加入游戏”。无需邀请码或独立座位链接。
2. 系统优先分配未满的等待房间，满五人后为新玩家创建下一个房间。
3. 每人点击准备，五人全部准备后自动开始，不需要裁判。
4. 同一浏览器重新加入会恢复尚未结束的对局和座位；同一浏览器的多个标签页视为同一玩家。
5. 等待开局时离线超过两分钟会释放座位；对局开始后不释放、不补人，离线仍按原规则计时。
6. 选数并确认提交后不可修改，全员提交或时间截止时自动结算。
7. 阅读结果和追加规则，存活玩家全部准备后进入下一轮。淘汰玩家可继续观看，结束后从首页加入新局。

这是自动匹配模式，拿到网址的其他访客也可能进入等待房间；好友可使用下方的好友房入口，房间码用于加入，当前没有额外密码。

## 好友房与自选机器人

首页输入昵称，展开“好友房 · 自选机器人数量”，创建房间；朋友输入房间码加入。房主在等待页勾选需要的机器人并保存，0～4 名均可，每种最多一名。两名真人可选三名机器人；五名真人可不选机器人。合计必须满五人，且所有真人准备后才开始。增加真人或更改机器人阵容会清除真人的准备状态；开局后不可更换阵容。

好友房不参与自动匹配，也不自动踢出等待玩家。同一浏览器使用原房间码恢复座位；房主再次创建会恢复自己未结束的好友房。房主负责选择机器人，不是裁判。每轮结束后机器人自动准备，仍需所有存活真人准备；所有真人淘汰后自动进行机器人对局。服务器重启后房间消失。

## 规则

- 5 人开局，每人 0 分。选择 0～100 的整数。
- 已提交数字平均数 × 0.8 为目标，距离最近者胜出，同距离并列获胜；其余提交者扣 1 分。
- 分数 ≤ −10 淘汰。剩 1 人结束；若同时全部淘汰，则无最终胜者。
- 剩 4 人：重复数字不能获胜，但仍计入平均数。首次淘汰前若连续两轮全员已提交且每轮选数完全相同，则在第二轮正常记分后播报规则 1 提前解锁，下一轮生效；两轮的共同数字可以不同。超时或当轮选数不一致会中断连续计数。提前解锁后不重复播报规则 1，其余规则仍分别在剩三人、两人时追加。
- 剩 3 人：获胜者选数等于目标值四舍五入后的整数时，视为精确命中，其他已提交失败者扣 2 分；超时者仍扣 1 分。
- 剩 2 人：一方选 0、另一方选 100 时，100 获胜。
- 规则累积生效，界面只显示已解锁内容。同轮淘汰多人时，按顺序列出跨过的追加规则，准备按钮同时确认已读。
- 首轮和新增规则后的轮次 5 分钟，普通轮 3 分钟；全员提前提交则立即结算。
- 网络版改编：超时未提交扣 1 分，不计平均数、不参与争胜；全员超时则每人扣 1 分。
- 胜负使用原始目标值比较距离；仅“精确命中”加罚条件使用目标值四舍五入后的整数。结果展示保留至四位小数。

## 网络与隐私边界

- 服务器统一维护截止时间；掉线不会暂停，刷新后恢复本座位、提交值和计时。页面每秒串行同步，失败自动重试。
- 浏览器生成随机身份凭证，保存在 localStorage；通过 Authorization 请求头使用，不放在网址中，也不向其他玩家返回。
- 服务器按凭证恢复或分配座位，重复加入不重复占座，提交前不向其他玩家返回数字；每次提交匹配轮次，提交后锁定。
- 请勿清除浏览器网站数据或切换浏览器，否则不能恢复原座位。共用一个浏览器视为同一玩家；本版没有账号登录与跨设备找回。
- 房间只保存在服务器内存，服务器重启后消失。浏览器刷新恢复不等同于服务器重启恢复。
- 旧裁判页及 start/next/reset 接口不再开放。
- 同 Wi-Fi 设备需能访问服务器端口。公网游玩使用部署后的 HTTPS 地址。

## 验证

运行 `npm test`。十八组测试覆盖自动分房、并发占座、身份恢复、等待座位释放，以及五人准备、隐私、身份校验、重复/过期提交、倒计时、追加规则、同时淘汰与完整对局。另覆盖机器人依据历史调整、私密预选、模式隔离，以及正常计分直至单人对局结束。自动化检查不代替五台真实设备的网络验收。

## Render 免费试玩部署

仓库根目录已准备 `render.yaml`，只创建一个 Free Web Service，不创建付费数据库。

1. 注册 GitHub 与 Render 账号（已有 GitHub 可直接使用），在 Render 连接存放此项目的仓库。
2. 建议建一个独立的私有 GitHub 仓库，只上传本项目的 `render.yaml` 和整个 `方片K` 文件夹，保持目录结构不变。
3. 在 Render 选择 New → Blueprint，选择该仓库，使用根目录 `render.yaml`。确认服务计划为 Free，再创建。
4. 如果手动选择 New → Web Service，则填写：Language = Node，Root Directory 留空（该字段不接受中文），Build Command = `node --test "方片K/server.test.js"`，Start Command = `node "方片K/server.js"`，Instance Type = Free，环境变量 `NODE_VERSION=22`，Health Check Path = `/health`。
5. 部署成功后，把服务提供的 HTTPS 首页地址发给朋友；不要发 localhost、局域网 IP 或玩家页地址。
6. 首次冷启动可能约一分钟，等待后再加入。使用五个独立浏览器身份检查是否进入同房、准备开局、私密提交及刷新恢复。

Free 服务空闲 15 分钟会休眠，也可能被平台重启；内存中的房间会丢失。本版不承诺对局持久保存，不应开多个服务实例。

## 单人挑战

首页点击“单人挑战 · 对战四位机器人”，即可与四名机器人进行独立的五人对局；空昵称默认为“挑战者”。点击准备开局，后续每轮播报结束后再点击准备。所有人从 0 分开始，按正式规则计分、淘汰；玩家被淘汰后，机器人自动继续，玩家可以观战至结束。

- 砺石（直觉）：以观察到的行为作一层判断，偏重生存。
- 逐流（推理）：在基础预测上，考虑对手的一次回应。
- 算子（深算）：再多模拟一次对手回应。
- 逆锋（适应）：用公开历史检验一至三层的预测误差，选择较合适的层次。

机器人仅根据本局已公布的选数、目标值、存活人数和积分估计对手行为，再比较 0～100 每个整数的模拟结果。少量随机性用于预测的不确定性和接近的候选方案，并非直接随机选数。它们在每轮开始时独立确定数字，约 2～6 秒后提交，不读取本轮玩家输入，也不共享彼此的预选数字。无需外部 API、账号或模型服务。

深度不是直接把上一轮平均数反复乘 0.8：先预测各座位行为，再模拟对手同时回应，最后按正式计分规则评估自己的选数。若已识别出明确的重复或交替规律，则优先相信证据；两人阶段直接评估 0/100 等实际规则，深算不保证更强。

预测分别评估每个对手的中位习惯、最近选数、有限趋势、交替模式与历史反应，并用历史误差调整可信度。一次高数不会立即重置整桌预测；持续变化会逐步获得支持。不同预测作为独立情景参与计算，避免把 0/100 交替误当成固定 50。重复失效后更重视撞号概率，濒临淘汰时停止对领先者施压的额外偏好。所有座位按同一套公开信息处理，不识别或针对人类身份。

本局最多保留最近 12 轮公开历史用于策略；新局清空，不跨局追踪玩家。机器人会适应，但不保证不会出现相同选数，也不保证具有人类水平的博弈能力。连续两轮全员同数会提前解锁重复失效规则，不依赖机器人主动牺牲。单人挑战与真人匹配、流程演示互相隔离；同一浏览器可恢复未结束的单人局。

## 单人流程演示与淘汰播报

首页“只看流程演示（预设淘汰）”创建独立房间，四名模拟玩家自动选数；每轮将指定玩家预设为 −9 分以快速演示淘汰。前三轮依次展示三条追加规则，第四轮展示体验者被淘汰和最终胜者。这是流程预览，不是 AI 公平对战，不进入真人匹配。

正式局与演示局：每轮结算后先播报记分 12 秒，显示选数、平均数、目标值、胜者、逐人扣分与累计积分；若有人淘汰，在记分顶部显示淘汰名单。记分结束后，如有新规则，再单独播报 12 秒。记分阶段服务器暂不公开新规则，记分播报结束后，追加规则可点击右上角关闭并提前准备；每位存活玩家均准备后才能进入下一轮；刷新恢复当前阶段与剩余时间。弹窗关闭后，追加规则仍留在规则面板。被淘汰者有常驻提示，无法提交或准备，可继续观战。结束时不再公布无后续对局可用的新规则。
